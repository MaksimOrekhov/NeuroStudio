# NS-027 — Adaptive Depth Conditioning

27 ноября 2026 · База: `main` после слияния PR #28 (`0f1bed29aff69720bdbd6c8a1dd1f2b9f91fad06`).

## Итог

**Этап A.** Выполнены три A/B-пары с ND-P25 (контрапост, рука на бедре): Crimson Oath, Duskrose и IllustrijN. Генерация шла на production-графе в рабочем разрешении 1440×2176 с крупностью «от головы до середины бедра». Отправлено 6 графов в ComfyUI, получено 6 PNG, ошибок, OOM и повторных отправок не было. Во всех трёх парах кадр с Depth лёг на контур карты: три четверти, вес на одной ноге, локоть отведён с ясным просветом, свободная рука вдоль тела. Ни один Baseline этой позы не дал: все три стоят фронтально, у двух рука на бедре, у IllustrijN её нет. Кисти, лицо, стиль модели и крупность Depth не ухудшил. Плата за Depth — около 6 % ко времени сэмплинга (3–4 с на кадр). Пик VRAM в пределах шума. Оценка техническая, на одном seed для каждой модели. Победителей выбирает пользователь.

**Этап B.** Ниже предложена архитектура: локальная Depth-библиотека вне git, проверка совместимости на сервере после planning-запроса, вставка трёх нод в граф отдельного кадра и запись фактического conditioning. Production-код в NS-027 не менялся. Интеграция начнётся только после визуального ревью.

### Подготовка карты

Production-граф задаёт разрешение через `ResolutionSelector` (2:3, 3 Мп, кратность 20): 1440×2180, латент 180×272, итоговый PNG **1440×2176**. Это совпадает с изображениями реальных коллекций. Время кадра там около 58 с. `AnimaLLLiteApply` в ComfyUI 0.46.3 масштабирует карту под латент бикубически с `crop="center"`. Поэтому карта с другими пропорциями обрезалась бы по центру. Чтобы этого не случилось, карта готовится сразу в размере латента.

Крупность выбрана по 127 кадрам из 40 последних сохранённых Prompt Plans. «От головы до середины бедра» встречается в 35 кадрах в разных формулировках. Это самая частая крупность. Дальше идут «до колен» (24) и полный рост (21). Это первая крупность ND-P25 в каталоге и правило Creative Director для вида сзади.

Подготовка (скрипт `output/ns-027/depth-pilot/scripts/prep_map.py`, локально, в git не входит):

- один seed на модель, один общий промпт, общий seed для всех моделей. Поэтому три Baseline похожи по композиции между собой;

- нужна визуальная оценка пользователя. Вероятно, понадобится и повтор на 2–3 seed. Этот шаг согласуется отдельно.

## Этап B — план интеграции (не реализован)

### Принципы

- Depth выключен по умолчанию и включается только вместе с режимом поз «Авто».
- Применяется только запись библиотеки со статусом `verified`, совпавшая с фактическим кадром по позе, модели, ракурсу и крупности. При любой неясности кадр генерируется обычным текстом. Сервер ничего не угадывает в пользу Depth.
- Дополнительных вызовов Codex нет. Решение принимает сервер после существующего planning-запроса.
- Общий workflow и его загрузка не меняются. Ноды вставляются в копию графа конкретного задания, которую уже создаёт `applyParams`.
- Карты и сама библиотека в git не попадают.

### Локальная Depth-библиотека

Папка вне git: по умолчанию `local/depth/` (добавить в `.gitignore`), переопределяется через `NEUROSTUDIO_DEPTH_DIR`. В ней `library.json` и PNG карт. В репозиторий входит только загрузчик с валидацией и пример схемы без карт и без ID исходной галереи.

- `views`, `crops`, `viewpoints` — ID опций из `src/composition.ts`, как в Pose Catalog. Это подмножество допустимых значений позы каталога, а не копия.
- `status`: `candidate` (тестировалась, ждёт ревью) → `verified` (одобрена пользователем) → `rejected`. Автоматически применяется только `verified`. `experimental` — для ND-P26 и подобных: хранится, но не применяется.
- `models` — только проверенные модели. Новая модель не наследует совместимость.
- У одной позы может быть несколько карт для разных комбинаций ракурса и крупности. У позы может не быть ни одной карты — это нормальный случай.
- При загрузке проверяются схема, существование `poseId` в текущем каталоге, ID опций композиции, уникальность ID, наличие файла, SHA-256 и размер PNG. Неверная запись исключается и попадает в журнал запуска. Остальные записи работают, генерация не прерывается.
- Новые карты добавляются вручную, по одной, после согласования. Массового наполнения и скриптов скачивания нет.

### Решение по кадру

После `validateBatch` и до `buildJobs` сервер вызывает чистую функцию `decideDepth(frame, model, library, env)` для каждого кадра. Порядок проверок и причина отказа:

| # | Проверка | Причина отказа |
| --- | --- | --- |
| 1 | `poseId` задан и не `free` | `free-pose` / `no-pose` |
| 2 | В библиотеке есть запись `verified` для `poseId` | `no-map` / `map-not-verified` |
| 3 | Модель кадра в `models` записи | `model-not-compatible` |
| 4 | Ракурс кадра однозначен и входит в `views` | `view-unclear` / `view-mismatch` |
| 5 | Крупность однозначна и входит в `crops` | `crop-unclear` / `crop-mismatch` |
| 6 | Высота точки съёмки не противоречит `viewpoints` (явные high/low angle) | `viewpoint-mismatch` |
| 7 | Разрешение графа равно `size` карты | `size-mismatch` |
| 8 | Файл карты на месте и SHA-256 совпадает | `map-missing` / `hash-mismatch` |
| 9 | ComfyUI видит `AnimaLLLiteApply` и адаптер в списке `ModelPatchLoader` | `adapter-unavailable` |
| 10 | Smooth Booster выключен (`90:89 = false`) | `booster-untested` |

**Ракурс и крупность.** Если в кадре заданы явные требования композиции (`orientation`, `framing`), используются они. Иначе последний блок промпта разбирается собственным строгим классификатором Depth-модуля. Ракурс должен быть ровно один из списка; `three-quarter view` без `rear` считается видом спереди в три четверти. Крупность тоже должна быть ровно одна: учитываются формулировки, реально встречающиеся в планах, например `head to mid-thigh`, `head-to-mid-thigh composition`, `mid-thigh composition`. Матчеры `server/promptFeatures.ts` не меняются, потому что они кормят статистику Prompt Evolution. Если формулировка не распознана, кадр идёт текстом. Сторону руки на бедре классификатор не проверяет: сторону задаёт карта. Это записывается в ограничения.

Проверки 7–9 выполняются один раз на запуск. Перед первой отправкой сервер загружает каждую нужную карту в ComfyUI через `/upload/image`: `type=input`, подпапка `neurostudio-depth`, имя `<mapId>-<sha12>.png`. ComfyUI не создаёт дубликат, если файл с тем же содержимым уже есть. В `LoadImage` подставляется имя, которое вернул сервер. Адаптер в общую папку `model_patches` Desktop кладёт пользователь сам, один раз. Это отдельное согласованное действие с учётом лицензии CircleStone. Если адаптера нет, все кадры генерируются текстом с причиной `adapter-unavailable`, запуск не падает.

### Вставка в граф

`applyDepth(graph, decision)` в `src/comfy.ts` работает с копией графа задания:

1. Находит KSampler по `FIELDS.seed` и запоминает его текущую связь `model`. Сейчас это `["90:84",0]`, после переключателя Smooth Booster.
2. Добавляет `LoadImage`, `ModelPatchLoader` и `AnimaLLLiteApply` с параметрами записи под зарезервированными ID (`ns-depth:image`, `ns-depth:patch`, `ns-depth:apply`; ID проверяются на коллизию).
3. Переключает `KSampler.model` на выход `AnimaLLLiteApply`.

Ровно так собраны графы этапа A. `buildJobs` получает решения по кадрам, и все seed-варианты кадра наследуют одно решение. Базовый граф `deps.baseGraph` не мутируется. Это проверяет существующий принцип `applyParams` плюс отдельный тест.

### Метаданные

Новое поле `conditioning` в `FrameRecord` и sidecar. Оно появляется, только когда Depth был запрошен:

```json
{ "mode": "depth", "mapId": "nd-p25-fq-h2mt-01", "mapSha256": "d9ed…", "adapter": "anima-lllite-depth-1.safetensors",
  "adapterSha256": "8135…", "strength": 1, "startPercent": 0, "endPercent": 1, "libraryVersion": 1, "comfyImage": "neurostudio-depth/nd-p25-fq-h2mt-01-d9edd45bd55f.png" }
```

```json
{ "mode": "text", "depthRequested": true, "reason": "crop-mismatch", "detail": "frame: knee_up; map: head_to_mid_thigh" }
```

- `generation.depth = { mode: "auto", libraryVersion }` в `collection.json`. В `batch-plan.json.depth` — решения по всем кадрам, включая отказы.
- `pose` (запланированная поза) и `conditioning` (что фактически ушло в граф) хранятся раздельно. Ни одно из них не означает, что PNG проверен визуально. Интерфейс пишет «Depth-карта применена», а не «поза подтверждена».
- Причины отказа попадают в `memory.poses` только как данные для будущего анализа. Ранжирование поз от них не меняется.
- Без Depth поле не пишется вовсе. Старые коллекции и обычные кадры выглядят как раньше.

### Seed-варианты и targeted regeneration

- **Seed-варианты** в запуске получают одно решение на кадр. Граф каждого варианта содержит те же три ноды и ту же карту, отличается только seed.
- **Перегенерация без правки промпта** уже берёт фактический граф из sidecar источника (`src/regenerate.ts`), поэтому Depth-ноды сохраняются автоматически. Добавляется наследование `conditioning`. Перед отправкой `checkDependencies` проверит, что карта видна в `LoadImage`. Если карты нет (например, ComfyUI переустановлен), сервер повторно загружает её из библиотеки по `mapSha256`. Если карты нет и в библиотеке, перегенерация отклоняется с понятной ошибкой. Пользователь может явно выбрать «без карты». Тихой подмены на текст нет.
- **Перегенерация с правкой positive.** Карта задаёт силуэт сильнее текста. Это видно в NS-025, где без Depth модель зеркалила позу, а с Depth нет. Поэтому новый текст про другую позу, ракурс или крупность даст конфликт: например, «сидит» при стоячей карте. Предлагается:
  1. Если у источника был Depth, интерфейс показывает флажок «Сохранить Depth-карту позы».
  2. Сервер прогоняет изменённый промпт через тот же классификатор ракурса и крупности, плюс простой признак позы стоя/сидя/лёжа. Совпадение — флажок включён. Конфликт или неясность — флажок выключен, рядом причина («крупность изменена на полный рост»).
  3. Решает пользователь. API принимает `depth: "keep" | "drop"`. Без правки промпта по умолчанию `keep`. С правкой и конфликтом без явного выбора — ответ 409 `DEPTH_CONFLICT`, ничего не отправляется.
  4. `drop` удаляет три ноды и возвращает `KSampler.model` на прежнюю связь. В `conditioning` пишется `{ mode: "text", droppedFrom: "nd-p25-fq-h2mt-01" }`.
  5. `keep` при правке сохраняет `conditioning.mode = "depth"` и ставит `promptAsPlanned: false`, как уже делает NS-026 для позы.

### Настройки и обратная совместимость

- Поле запроса `depthConditioning: "off" | "auto"`. Если поля нет — `off`. Значение `auto` принимается только при `poseSelection: "auto"`, иначе ответ 400 до запуска, по образцу `parsePoseMode`.
- В блоке «Позы» добавляется переключатель «Depth-карты (экспериментально)», активный только в режиме «Авто». Выбор хранится в `localStorage` (`neurostudio.depthMode`), по умолчанию выключен. В сводке генерации — строка «Depth: …». На странице коллекции у кадра — пометка о применённой карте или причина, по которой её не применили.
- При `off` запрос Codex, схема, графы, `batch-plan.json`, `collection.json` и sidecar остаются байт в байт как в NS-026. Это проверяется тестом.
- Старые коллекции без `conditioning` читаются и перегенерируются как раньше.

### Риски и открытые вопросы

- **Сторона руки.** Карта фиксирует руку на бедре слева в кадре. Если Codex напишет «left hand on hip», текст и карта разойдутся. В A/B этот случай не проверялся. Варианты: зеркальная копия карты как отдельная запись библиотеки или явная сторона в записи. Оба требуют своего теста.
- **Смена версии ComfyUI.** Между NS-025 и NS-027 Desktop обновился с 0.46.1 до 0.46.3. `checkDependencies` ловит пропажу ноды, но не изменение её поведения. После обновления стоит повторить одну контрольную пару.
- **Лицензии.** Адаптер распространяется по некоммерческой лицензии CircleStone. Карты POSE-DB-02 разрешены как единичный референс, без перераспространения. Обе лицензии совместимы с текущим некоммерческим использованием и требуют пересмотра при любой монетизации.
- **Smooth Booster.** Depth проверен только при выключенном Smooth Booster (35 шагов, CFG 4). Сейчас сервер его не включает: переключателя `90:89` нет в `FIELDS`. При включённом режиме (8 шагов, CFG 1) поведение неизвестно, поэтому проверка 10 оставляет такой кадр текстовым.
