# NS-031 — Image Repair MVP (ручной локальный ремонт)

28 ноября 2026 · База: `main` после слияния PR #32 (`9be906c`) · Ветка `ns-031-image-repair-mvp`.

Основа — пайплайн, проверенный в NS-030 (PR #33): Anima LLLite Inpainting v2, маска шума латента и финальное композитирование.

## Что сделано

**Интерфейс** — Vue 3, TypeScript, Composition API, существующие компоненты.

На карточке кадра и в просмотрщике добавлена кнопка **«Исправить область»**. Она активна только для изображений Crimson Oath v0.3; для других моделей в подсказке написано почему.

Диалог `RepairDialog.vue`:
- изображение с маской поверх;
- кисть и ластик, размер кисти, «Отменить» (Ctrl+Z), «Очистить», доля кадра под маской;
- два пресета: **«Удалить объект»** (denoise 1.0) и **«Локальное исправление»** (denoise 0.65);
- описание исправления на английском;
- свёрнутый блок «Параметры»: ползунок denoise (0.30–1.00, изменённое значение помечается как «свой») и область обработки 512 или 1024 px.

Strength фиксирован — 1.0, seed каждый раз новый. Перед запуском диалог проверяет маску и описание по тем же правилам, что сервер, и показывает причину, если запуск невозможен.

Маска хранится как список штрихов в пикселях изображения, поэтому отмена точная. Отправляется PNG размера исходника: белое — исправить.

**Генерация** — `src/repair.ts`, `AutopilotRunner.startRepair`. Только нативные ноды ComfyUI 0.46.3, граф совпадает с графами NS-030:

```
LoadImage(кроп) ─[ImageScale lanczos ×2 для 512]─► VAEEncode ─► SetLatentNoiseMask(grow) ─► KSampler ─► VAEDecode ─[ImageScale area]─┐
UNETLoader ─► AnimaLLLiteApply(inpainting-v2, image = кроп, mask = grow, strength 1.0, 0–1) ─► KSampler                                │
LoadImage(исходник) ─► ImageCompositeMasked(x0, y0, mask = blend) ◄────────────────────────────────────────────────────────────────────┘ ─► SaveImage
```

- **Параметры из графа исходника:** модель, CLIP, VAE, negative, шаги, CFG, сэмплер, планировщик.
- **Positive** = quality prefix исходника + style phrase (если она была) + описание пользователя. Описание героини, позы и кадра в него не входит — так NS-030 показал лучший результат. Codex не вызывается.
- **Маски:**
  - `grow` — нарисованная маска, расширенная на 16 px (точное евклидово расширение);
  - `blend` — `grow` с гауссовым размытием σ 6. Значение 0 означает, что пиксель исходника сохраняется.
- **Область обработки** — квадрат 512 или 1024 px вокруг зоны ремонта, внутри кадра, по возможности кратный 16. Область 512 увеличивается до рабочих 1024 и затем уменьшается обратно.
- **Модели:** разрешена только Crimson Oath v0.3. Проверяются и id модели, и checkpoint в графе. Источник со Smooth Booster не принимается. Другие модели не объявляются совместимыми.

**Проверки до отправки.** Нарушение любой проверки ничего не резервирует и не загружает в ComfyUI.
1. Тело запроса: PNG-маска, текст на английском, denoise 0.3–1.0, область 512 или 1024.
2. Маска: размер совпадает с исходником; не пустая; не больше 25 % кадра; зона с границей помещается в выбранную область.
3. Модель и граф исходника.
4. ComfyUI:
   - доступен;
   - есть все ноды;
   - у `AnimaLLLiteApply` есть вход `mask`;
   - адаптер есть в списке;
   - доступны файлы модели, CLIP и VAE, сэмплер и планировщик.
5. После загрузки входов — `checkDependencies` по готовому графу.

**Выполнение.**
- Блокировка общая с обычной генерацией и перегенерацией, параллельных GPU-задач нет.
- Одна отправка, без повторов.
- Если задачу приняли, а ответа нет, вариант получает статус «состояние неизвестно» (prompt_id сохраняется), как при перегенерации.

**Гарантия сохранности.** После загрузки результата сервер сравнивает каждый пиксель итогового PNG с исходником там, где `blend` = 0. Если хоть один пиксель отличается, результат не сохраняется как вариант: вариант получает статус «ошибка», а PNG откладывается в `repairs/<имя>/rejected-final.png` для разбора.

**Хранение.** Результат — новый вариант кадра `scene-NN-vMM.png`. Номер и защита от перезаписи — как у перегенерации.
- **В `collection.json`:** `sourceVariant` и краткое поле `repair` (метод, пресет, denoise, strength, область, кроп, текст, файлы).
- **В sidecar `scene-NN-vMM.json`:**
  - точный отправленный граф;
  - positive, seed, prompt_id;
  - базовые параметры (`repair.base`), исходник (вариант, файл, SHA-256, размер);
  - адаптер (файл, ожидаемый SHA-256, проверено только наличие);
  - маски (площади, рамка, SHA-256), имена загруженных в ComfyUI файлов;
  - результат проверки пикселей и время.
- **В `repairs/scene-NN-vMM/`:** `mask.png`, `grow.png`, `blend.png`, `raw-crop.png` (результат генерации до наложения).

Оригинал, его sidecar, оценки, сравнения и Best не меняются. Новый вариант можно выбрать лучшим и оценить как обычный.

**Перегенерация отремонтированных вариантов.** Граф ремонта не является графом генерации, поэтому перегенерация такого варианта явно запрещена:
- новый код ошибки `REPAIR_NOT_REGENERABLE`;
- кнопка «Перегенерировать» неактивна с подсказкой «перегенерируйте исходный вариант N»;
- неправильный граф не запускается.

Повторный ремонт уже исправленного варианта разрешён: модель и параметры берутся из записи первого ремонта (`repair.base`).

**Prompt Evolution не затронут.** Он читает промпт из ноды `90:77` графа варианта, а в графе ремонта таких id нет. Отремонтированные варианты просто не дают ему текста промпта.

## API

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/repair/status` | Готовность ComfyUI: ноды, вход `mask`, адаптер (только наличие в списке), список проверенных моделей. Если нет адаптера — инструкция по установке. |
| GET | `/api/collections/:id/frames/:frame/variants/:variant/repair` | Можно ли ремонтировать вариант; размер, доступные области, пресеты, ограничения |
| POST | `/api/collections/:id/frames/:frame/repair` | `{ sourceVariant, mask: "data:image/png;base64,…", text, denoise, region, preset }` → 202 и состояние запуска; 409 `ALREADY_RUNNING`, если что-то уже идёт |

Новые коды ошибок с русскими сообщениями:
- `REPAIR_NOT_REGENERABLE`;
- `REPAIR_MODEL_UNSUPPORTED`;
- `REPAIR_UNAVAILABLE`;
- `INVALID_MASK`.

## Зависимость: адаптер в ComfyUI Desktop

Адаптер `anima-lllite-inpainting-v2.safetensors` скачан в NS-030 и лежит в `output/ns-030/repair-pilot/comfy/models/model_patches/` (SHA-256 `5242e677…db6ef5`). **В Desktop он не установлен.** Повторно он не скачивается.

Пока его нет, ремонт отклоняется с `REPAIR_UNAVAILABLE`, а диалог показывает шаги установки:
1. скопировать файл в `model_patches` общей папки моделей Desktop;
2. проверить SHA-256;
3. перезапустить Desktop.

Установка — только с отдельного согласия пользователя.

## End-to-end smoke test (после ревью; не выполнялся)

`scripts/repair-smoke.ts` (`npm run smoke:repair`): одна реальная операция ремонта через работающий сервер и ComfyUI. Без `--confirm` скрипт не запускается и никогда не повторяет отправку. После ремонта он независимо от сервера проверяет на диске, что пиксели вне зоны не изменились.

Порядок:
1. Ревью реализации.
2. С согласия пользователя установить адаптер в Desktop и проверить SHA-256.
3. `npm start`.
4. Выбрать изображение Crimson Oath v0.3 с понятным дефектом.
5. Запустить:
   ```
   npx tsx scripts/repair-smoke.ts --collection <id> --frame N --variant V --disc x,y,r --text "<что должно быть>" --preset remove --region 1024 --confirm
   ```
6. Визуально оценить новый вариант.

## Ограничения MVP

- Только Crimson Oath v0.3. Остальные модели — после отдельной проверки.
- Восстановление кистей нестабильно (NS-030): для удаления лишнего лучше «Удалить объект», для мелких правок формы — «Локальное исправление» с областью 512 px.
- Наличие адаптера проверяется по списку ComfyUI, а не по хешу установленного файла.
- Не реализованы: автоматическое обнаружение дефектов, автоматические маски, vision-модели, автоматический цикл ремонта.
- Не менялись: обычная генерация, Creative Director, Prompt Evolution, Auto Mix, Depth и Pose.
