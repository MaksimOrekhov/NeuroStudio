### Выводы для практического использования

- **Метод — Inpainting v2 с маской шума латента и финальным наложением.** Обычный masked img2img хуже во всех трёх случаях.
- **Удаление объекта:** denoise 1.0. Удаляемое не должно оставаться в исходной структуре.
- **Локальная правка с сохранением формы:** denoise 0.65. Сохраняет форму, но может сохранить и часть дефекта.
- **Текст ремонта описывает, что должно быть на месте дефекта и как продолжается окружение**, а не всю сцену и не героиню.
- **Малая область выигрывает от увеличения:** кроп 512 с масштабом ×2 дал лучшую анатомию кисти.
- **Скорость:** 15–19 с на ремонт при свободном CPU. При загруженном CPU — до 45 с: адаптер готовит условие на CPU каждый шаг.
- **Память:** пик VRAM 8.2–8.4 GiB, адаптер его не повышает.

**Предварительно, по одному seed на случай и одной модели (Crimson Oath v0.3):**
- **Inpainting v2 лучше обычного masked img2img во всех трёх случаях.** Дефект устранён в двух из трёх (зеркало и стопа), у img2img — в одном (зеркало).
- **Удаление объекта** (фигура, лишняя стопа) адаптер решает. Обычный img2img при denoise 1.0 видит контекст только через латенты вокруг и может заново нарисовать тот же объект.
- **Перерисовка кисти целиком** не удалась ни одному методу. Inpainting v2 дал анатомически неверную кисть, img2img — её отсутствие.
- **Сохранность вне ремонта гарантирована:** во всех шести итоговых PNG вне переходной зоны изменено **0 пикселей**. Маска ограничивает изменение латента в обоих методах, а не только финальное наложение (раздел «Этап B»).
- **Скорость.** img2img — 14–18 с на ремонт. Inpainting v2 — 16–43 с: адаптер каждый шаг готовит условие на CPU, и при занятом процессоре GPU простаивает.

## Итог этапа A

**Задача.** Проверить, можно ли исправлять локальные дефекты готовых изображений без полной перегенерации. Цель — больше пригодных изображений. В отличие от NS-025–029, управлять исходной позой не нужно: нужно восстановить проблемную область уже готового кадра и не испортить остальное.

**Главное.**

- Адаптер получает **4 канала**: RGB с вырезанной областью и бинарную маску. Он видит контекст вокруг дыры, но не видит пиксели внутри неё.
- **Установленный ComfyUI 0.46.3 поддерживает маску нативно.** У `AnimaLLLiteApply` есть необязательный вход `mask`. Код обработки 4-канального входа проверен по исходникам. Custom nodes и обновление Desktop не нужны.
- **Рекомендованных strength, denoise и CFG нет** ни у автора, ни у Comfy-Org. Автор советует только img2img с маской, иначе «цвета могут немного сместиться».

- **Baseline без адаптера** — обычный masked img2img: `VAEEncode` → `SetLatentNoiseMask` → `KSampler`. Тоже только нативные узлы.
- Подобраны **три исходника на Crimson Oath v0.3** с разными дефектами: третья стопа, посторонняя фигура в зеркале, складка у манжеты со сдвоенными пальцами. Подготовлены маски, кропы 1024×1024 и шесть графов.

### Архитектура и обучение v2

По карточке kohya-ss и руководству sd-scripts:
- **Базовая модель — Anima-Base v1.0.** VAE Qwen-Image, текстовый энкодер Qwen3-0.6B.
- **Условие — 4 канала.** RGB-изображение, в котором область маски обнулена (`--lllite_inpaint_masked_input`), плюс бинарная маска. Маска бинаризуется по порогу 0.5 и переводится в {−1, 1}. Белое (1) — перерисовать, чёрное (0) — сохранить.
- **Данные.** 4 000 изображений Anima по случайным промптам. Условие — само исходное изображение, маска случайная и генерируется на каждом шаге обучения. Пользовательские маски при обучении не использовались, автор помечает функцию как экспериментальную.
- **Параметры.**
  - внедрение в `self_attn_q_pre`, `self_attn_kv_pre`, `mlp_fc1_pre`, то есть Q, K, V и первый слой MLP каждого из 28 блоков DiT;
  - `cond_resblocks` 4, `cond_emb_dim` 64, `cond_dim` 128, `mlp_dim` 64;
  - lr 1e-3, flow shift 3.0, batch 12, caption dropout 0.15 — для поддержки CFG.
- **Разрешение.** Бакеты от 512² до 1536² по площади.
- **Опубликованная точка.** Эпоха 30 из запланированных 64, около 10 770 шагов и 17.5 ч обучения. Loss ещё снижался, обучение остановлено, чтобы избежать переобучения.
- **Ограничение.** Только одиночный кадр (T=1).

### Официальный workflow

Шаблон «Anima LLLite: Image Inpainting» — единственный официальный, который использует v2 (страница Hub: «1 workflow uses this file»).

| Узел | Значение |
| --- | --- |
| `LoadImage` → `Painter` | Маска рисуется ластиком прямо поверх изображения. `Painter` отдаёт изображение и маску. |
| `UNETLoader` | `anima-base-v1.0.safetensors` |
| `ModelPatchLoader` → `AnimaLLLiteApply` | inpainting-v2; strength 1, start 0, end 1. Вход `image` — исходник, `mask` — маска Painter. |
| `EmptyLatentImage` | 1024×1024 |
| `KSampler` | euler / simple, **denoise 1**. Без turbo: 30 шагов, CFG 4. С turbo LoRA (`anima-turbo-lora-v0.2`, включена по умолчанию): 8 шагов, CFG 1. |
| `SaveImage`, `ImageCompare` | Результат и сравнение с исходником |

Заметки шаблона советуют уменьшать изображения больше 1024×1024.

**Главное отличие от нашего плана.** Шаблон генерирует **всё изображение с нуля** из пустого латента. Область вне маски воспроизводится только через условие адаптера и поэтому меняется. Узлов `VAEEncode`, `SetLatentNoiseMask` и `ImageCompositeMasked` в нём нет. Автор адаптера рекомендует обратное — img2img с маской. Поэтому пилот следует рекомендации автора, а не шаблону (см. «Экспериментальные графы»).

Все узлы шаблона, включая `Painter`, `ComfySwitchNode` и `PrimitiveBoolean`, нативные в 0.46.3. Шаблон загрузится без custom nodes, если поставить модель и LoRA, но нам он не нужен.

### Поведение за пределами маски

- **Адаптер сам по себе (как в шаблоне).** Вне маски модель перерисовывает изображение по условию. Получается близко к исходнику, но не тождественно: автор предупреждает о смещении цвета.
- **С `SetLatentNoiseMask`.** На каждом шаге латент вне маски возвращается к исходному с соответствующим уровнем шума, а в конце заменяется исходным латентом (`comfy/samplers.py`, строки 638–642). Различия в пикселях остаются только из-за двух вещей:
  - декодирование VAE (round trip кодер → декодер);
  - мягкий край маски: она уменьшается до сетки латента 1/8 билинейно.
- **С финальным композитированием.** Пиксели, где маска композиции равна 0, берутся из исходника байт в байт (см. ниже).

### Память

| Параметр | Оценка |
| --- | --- |
| Файл | 65.8 МБ. Это почти втрое больше Pose (23.3 МБ) из-за `mlp_layer1` и `cond_dim` 128. |
| VRAM адаптера | Десятки МБ весов. Основной прирост — активации условия на каждом шаге. |
| Кроп 1024×1024 | 4 096 токенов против 12 240 у кадра 1440×2176. Пик ожидается ниже, чем у полноразмерного Baseline в NS-028 (8 350–9 412 MiB). |
| Время | В NS-029 при 1440×2176 — около 1.6 с/it. На кропе ожидается заметно быстрее. Не измерено. |

Цифры — оценки. Пилот их измерит тем же монитором памяти, что в NS-027–029.

## Поддержка в установленном ComfyUI 0.46.3

Проверено по исходникам `comfy/ldm/anima/lllite.py` и `comfy_extras/nodes_model_patch.py`:

- **`AnimaLLLiteApply`** имеет необязательный вход `mask` типа MASK. Число входных каналов читается из веса (`lllite_conditioning1.conv1.weight`).
- **Для 4-канального веса:**
  - маска масштабируется до размера латента ×8 (`nearest-exact`, center crop) и бинаризуется по порогу 0.5;
  - если в метаданных `lllite.inpaint_masked_input` = `true`, RGB внутри маски обнуляется в пространстве [−1, 1]. В пикселях это средне-серый 0.5, а не чёрный;
  - маска добавляется четвёртым каналом как `mask·2−1`.
- **Без маски** 4-канальный вес молча получает пустую маску («ничего не перерисовывать»). Узел kohya-ss в этом случае выдаёт ошибку. Поэтому в графах маска подаётся явно.
- **Модули v2** (`self_attn_[qkv]_proj`, `cross_attn_q_proj`, `mlp_layer1`) входят в шаблон имён нативного загрузчика. Нужные для inpainting `mlp_layer1` поддержаны.
- **Управляющее изображение** масштабируется bicubic с center crop до размера латента ×8. Если пропорции кропа и латента разойдутся, условие сместится относительно маски. В наших графах управляющее изображение и латент получены из одного кропа 1024×1024 — совпадение точное.
- README kohya-ss утверждает, что нативный узел маску не принимает. Для 0.46.3 это **устарело**.

**Вывод: адаптер можно использовать без custom nodes и без обновления Desktop.** Для пилота нужен только файл весов.

**Проверка после загрузки, до первой отправки:**
- размер и SHA-256;
- `lllite.version` = "2";
- 4 входных канала у `conv1`;
- `lllite.inpaint_masked_input` = "true";
- имена модулей.

Если флага `inpaint_masked_input` нет, узел не обнулит вырез, и условие будет отличаться от обучающего. Тогда пилот останавливается до генерации, и вопрос выносится на согласование. Возможное решение — заранее залить вырез серым 0.5. Это эквивалентно обнулению и безопасно, даже если флаг есть.

## Masked img2img без адаптера (baseline)

**Схема:** `VAEEncode(кроп)` → `SetLatentNoiseMask(маска)` → `KSampler` → `VAEDecode`. Модель, промпт, seed и параметры — как у варианта с адаптером.

**Почему не другие узлы:**
- `VAEEncodeForInpaint` заливает область маски серым и расширяет её. Он рассчитан на модели, обученные inpainting. На обычной модели это даёт серые пятна, а при denoise меньше 1 уничтожает подсказку исходных пикселей.
- `InpaintModelConditioning` передаёт латент маски через concat-условие. У Anima такого входа нет.

**Чего ждать.** Обычная модель не знает, что внутри маски дыра. Контекст доходит до неё только через латенты вне маски, которые возвращаются на каждом шаге. Типичные слабые места:
- шов по краю маски;
- несогласованный свет и фактура;
- при неполном denoise — повтор исходного дефекта.

Именно это адаптер должен исправить. Поэтому сравнение «тот же граф ± адаптер» — минимальный честный эксперимент.

## Композитирование и сохранность пикселей

**Исходный PNG никогда не перезаписывается.**
- Исходники копируются в `output/ns-030/repair-pilot/sources/`, хеши сверяются.
- ComfyUI читает копии из своей папки input.
- Результаты сохраняются с префиксом `NS-030/` в отдельную папку output пилота.

**Схема.** Исправленный кроп накладывается на полный исходник узлом `ImageCompositeMasked` с маской композиции (blend).

**Проверено без GPU:**

| Проверка | Результат |
| --- | --- |
| Цепочка ComfyUI `LoadImage` (uint8 → float32 /255) → смешение с маской 0 → `SaveImage` (×255, clip, uint8) на всех 256 значениях байта | **0 расхождений** |
| Кроп → обратная вставка без изменений, 3 исходника | Байт в байт |
| Композиция со случайным «исправленным» кропом (худший случай) | Изменилось **0 пикселей** вне ненулевой зоны blend на всех трёх масках |

Значит, вне зоны blend итог совпадает с исходником байт в байт при любом результате генерации. На пилоте это ещё раз проверяется попиксельным сравнением каждого итогового PNG.

Отдельно сохраняется сырой декодированный кроп. По нему видно, что изменилось бы без композитирования: round trip VAE и мягкий край маски латента.

## План GPU-пилота (этап B; выполнен, см. «Этап B — пилот Inpainting»)

1. **Загрузка.** Скачать только `anima-lllite-inpainting-v2.safetensors` (Comfy-Org) в изолированную `output/ns-030/repair-pilot/comfy/models/model_patches/`. В Desktop не устанавливается. Сверить размер, SHA-256 и метаданные (раздел «Поддержка в установленном ComfyUI»). При расхождении — остановиться.
2. **Входы.** Положить в input пилота 12 файлов: по каждому кейсу полный исходник, кроп исходника, кропы grow и blend. Сверить хеши с `masks-record.json`.
3. **ComfyUI.** Изолированный 0.46.3 из venv Desktop, как в NS-029:
   - `127.0.0.1:8195`, `--offline`, `--disable-dynamic-vram`, SQLite в памяти;
   - своя `base-directory`, пустой `custom_nodes`;
   - instance-YAML Desktop плюс YAML пилота только для `model_patches`.
   - Перед стартом: версия и хеш v0.3, свободные порты, память. Затем проверка шести графов по `/object_info`.
4. **Генерация.** Шесть отправок строго последовательно, каждая только после успеха предыдущей, без повторов. Порядок — по кейсам: `img2img`, затем `inpaint`. Монитор памяти NS-027–029 с порогами RAM < 1 GiB, запас commit < 2 GiB, VRAM < 256 MiB. После шестой ComfyUI останавливается.

6. **Метрики сохранности** (скрипт, без GPU):
   - итог против исходника вне зоны blend — должно быть 0 изменённых пикселей;
   - сырой кроп против исходника вне grow — средняя и максимальная разница, PSNR (эффект round trip VAE);
   - разница внутри маски — карта отличий.
7. **Листы ревью:** исходный кроп | img2img | inpaint v2 | карты разницы. Плюс крупные фрагменты дефекта и края маски.
8. **Остановка** для визуального ревью.

**Предел — шесть генераций.** Повтор при ошибке, второй seed, другой denoise или strength — только по отдельному согласованию.

## Критерии оценки

| Критерий | Как оценивается |
| --- | --- |
| Устранён ли дефект | Визуально: одна ли стопа убрана, пусто ли зеркало, пять ли пальцев и нет ли складки |
| Новые анатомические ошибки | Визуально, крупный план: стопы, пальцы, контур кисти и голеней у края маски |
| Лицо, внешность, одежда | Лицо вне всех масок, значит не меняется по построению (проверяется метрикой). Одежда у края маски — визуально. |
| Стиль | Совпадение фактуры, освещения и резкости внутри и вокруг маски |
| Швы | Визуально по краю grow и blend, крупно. Карта разницы на краю. |
| Композиция | Вне зоны blend не меняется по построению. Внутри — нет ли новых объектов. |
| Пиксели вне маски | Итог: 0 изменённых пикселей вне blend. Сырой кроп: средняя и максимальная разница, PSNR. |
| Время | Время ComfyUI и с/it на прогон |
| RAM и VRAM | Пик VRAM, минимум RAM, пик commit; сравнение img2img и inpaint |

## Возможная будущая интеграция (предложение, не реализуется)

Только если пилот покажет пользу. Интерфейс опирается на механизм targeted regeneration NS-017 (`src/regenerate.ts`). Он уже создаёт новый вариант `scene-NN-vMM` рядом с исходным, не трогая его, и хранит `sourceVariant`.

1. **«Исправить область»** — кнопка в просмотре изображения рядом с перегенерацией.
2. **Маска.** Кисть и ластик поверх изображения, регулируемый размер кисти, отмена. Маска хранится отдельным PNG (белое = исправить) в разрешении исходника. Расширение и растушёвка применяются автоматически, параметры фиксированы (16 px, σ 6).
3. **Описание исправления.** Короткое поле, до 200 символов. Добавляется в конец исходного позитива, как в пилоте. Исходный промпт не редактируется.
4. **Новый вариант.** Результат сохраняется как новый `scene-NN-vMM.png`. Исходник не перезаписывается. Сервер сам выбирает кроп 1024×1024 вокруг маски.
5. **Сравнение.** Шторка «до / после» и переключатель, плюс подсветка изменённой зоны.
6. **Запись в `FrameRecord`** — новое поле `repair`:
   - `sourceVariant`, хеш исходника;
   - файлы маски и blend, кроп;
   - метод и адаптер с SHA-256;
   - фраза исправления;
   - модель, seed, шаги, CFG, сэмплер, denoise, strength;
   - хеш графа.
   
   Полный граф сохраняется рядом, как сейчас.
7. **Ограничения:**
   - маска не больше заданной доли кадра (например 25 %), иначе предлагается полная перегенерация;
   - один ремонт — одна генерация, без автоповторов.

Автоматический vision-анализ дефектов, автоматическое построение масок и автоматическое исправление — следующие задачи.
