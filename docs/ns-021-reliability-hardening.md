# NS-021 — Reliability Hardening

Исправления надёжности без новых пользовательских функций и миграции коллекций.

- `runCollection()` подтверждает `done` после сохранения PNG и sidecar JSON. Ошибка относится к текущему заданию; последующие остаются `pending`, готовые изображения и принятые `prompt_id` сохраняются. Повторной отправки в ComfyUI нет.
- Существующая атомарная запись вынесена в небольшой `src/persistence.ts`: уникальный временный файл на операцию, полная запись перед заменой, краткие повторы rename при Windows EPERM/EBUSY/EACCES. `src/regenerate.ts` сохраняет прежние экспорты helper/IO для совместимости. Manifest и batch metadata также записываются атомарно.
- Best и feedback сериализуются по коллекции. Ошибка не блокирует следующие операции. Ошибки записи возвращаются клиенту; предыдущий файл остаётся целым. Повреждённые Best/feedback не заменяются молча; удаление feedback игнорирует только ENOENT.
- GET библиотеки и открытой коллекции учитывают подтверждённые изменения Best, Image Feedback и feedback, произошедшие после начала запроса. Следующий свежий GET принимает серверное состояние, включая изменения другой вкладки.
- Polling обновляет открытую коллекцию вне последних 50 через её detail endpoint. Закрытые коллекции отдельно не запрашиваются; ответы от предыдущего открытия игнорируются.
- Общий обработчик запуска сохраняет `failed`, причину и код ошибки на этапах подготовки, обязательного snapshot, планирования и генерации. Ошибка анализа памяти по-прежнему разрешает продолжение без памяти. Ошибка записи snapshot останавливает запуск до Codex. Вторичная ошибка записи итогового статуса не подменяет исходную.
- `.github/workflows/ci.yml`: PR и push в main, Ubuntu, Node.js 22, `npm ci`, `npm test`, `npm run typecheck`, `npm run build`, лимит 5 минут.

## Проверка

20 новых регрессионных тестов в `tests/ns021.test.ts` и `tests/ns021-ui.test.ts` используют реальные app/runner/store с подменой внешних вызовов. Они проверяют ошибки частичной записи PNG/sidecar, независимые временные файлы, конкурентный Best/feedback, отказ записи/rename/unlink, повреждённые файлы, обязательный snapshot, ошибки до генерации и вторичные ошибки сохранения, управляемые задержки GET/PUT, перегенерацию старой коллекции и смену/закрытие detail.

Запуск: `npm test`, `npm run typecheck`, `npm run build`. Реальные Codex CLI, ComfyUI, GPU и платные сервисы не нужны. Полезные сценарии из `output/review-probes.ts` перенесены в обычные тесты; скрипт ревью не используется приложением или CI.

## Оставшиеся ограничения

- Очереди защищают запросы одного процесса сервера. Одновременная запись нескольких независимых экземпляров сервера в одну папку не поддерживается.
- Атомарная замена защищает целостность отдельного файла, но не является транзакцией нескольких файлов и не обещает сохранность при отключении питания. Частично завершённый PNG/sidecar не показывается готовым.
- Если файловая система отказывает и при записи итоговой ошибки, история может сохранить предыдущий полный статус. Исходная ошибка остаётся в текущем состоянии процесса; вторичный сбой сообщается в серверном логе. Автоматического повторного запуска нет.
- Проверки используют подменённые внешние зависимости; реальная генерация не запускалась.
