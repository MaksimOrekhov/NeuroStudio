# NS-026 — Adaptive Pose Selection v1

26 ноября 2026 · База: `main` после слияния PR #27 (`4725900`).

## Итог

Добавлен явный режим генерации «Авто — из библиотеки». В этом режиме сервер локально выбирает из курируемого каталога 8–12 поз и передаёт их в тот же единственный planning-запрос Codex. Codex сам решает, на какой позе строить каждый кадр, или ставит `free`, если ни одна не подходит. Кадр с явными требованиями композиции принимает только совместимые с ним позы. Выбранный `poseId` — это **запланированная** поза: на неё написан промпт кадра. Он сохраняется в плане, в записи кадра и в sidecar каждого изображения. Seed-варианты наследуют его, перегенерация сохраняет связь. Совпадение позы на готовом PNG ничто не проверяет. Режим «Свободный» остаётся по умолчанию: запрос, схема, валидация и метаданные в нём такие же, как до NS-026.

Ревью-правка (раздел «Ревью-правка» ниже):
- признак зависимости позы от окружения и ограничение доли поз с конкретным предметом;
- разнообразие выборки по ракурсам и крупностям;
- контракт `poseId` для каждого кадра;
- история ракурсов недавних коллекций с мягкой подсказкой для финального кадра;
- поле `promptAsPlanned` вместо `verified`.

## Архитектура

```
форма (poseMode) ─► POST /api/autopilot/start {poseSelection:"auto"}
                     │ parsePoseMode: отсутствует → "free"
                     ▼
AutopilotRunner.execute
  ├─ Preference Memory (если включён Prompt Evolution)
  ├─ недавние коллекции → avoid, визуальная история, использованные poseId (12 коллекций)
  ├─ selectPoses(каталог, композиция, seed, недавние позы, cautious) ─► batch-plan.json.poseSelection
  ├─ framePoseIds (допустимые id каждого кадра) + viewHistory/viewNote (ракурсы недавних планов)
  └─ ОДИН вызов Codex: planPrompt(... композиция, блок библиотеки + строки кадров + подсказка, предпочтения) + схема с enum poseId
                     ▼
validateBatch(poseIds = переданные id, framePoseIds = id каждого кадра)
  └─ buildJobs(plan, ..., catalogVersion) → Job.pose → FrameRecord.pose + sidecar.pose
```

Ошибка в каталоге останавливает запуск в режиме «Авто», молчаливой подмены нет. Данные AI Pose Gallery в каталог не входят: все описания оригинальные, новые референсы не загружались.

## Режимы

| Режим | Поведение | Запрос Codex | Метаданные |
| --- | --- | --- | --- |
| Свободный (по умолчанию) | Codex придумывает позы сам, как раньше. | Байт в байт как до NS-026. Схема без `poseId`. | Без новых полей. |
| Авто — из библиотеки | Codex выбирает позу для каждого кадра из выборки или ставит `free`. | Добавлен блок библиотеки, в схеме обязательный `poseId` с enum из переданных ID и `free`. | `batch-plan.json.poseSelection`, `generation.pose`, `frames[].pose`, sidecar `pose`. |

Новый режим включается только явно. В форме по умолчанию стоит «Свободный», выбор хранится локально (`neurostudio.poseMode`), как переключатель Prompt Evolution. API без `poseSelection` работает как раньше, неизвестное значение отклоняется с 400 ещё до запуска. Ручной выбор референса, превью библиотеки и Depth conditioning в NS-026 не входят.

## Выборка для Codex

`selectPoses` детерминирована: одинаковые входные данные, история и seed дают ту же выборку в том же порядке. Seed генерируется на каждый запуск и сохраняется в `batch-plan.json` вместе с ID выборки, учтёнными повторами и флагом `cautious`.

1. **Совместимость.** Учитываются явные требования к кадрам: поза, поворот, крупность. Поза, несовместимая ни с одним кадром, не попадает в выборку. Для каждого кадра с требованиями сначала берутся до трёх совместимых поз. Если совместимых нет, Codex использует `free`. Высота точки съёмки не ограничивает выбор.
2. **Вес.** Порядок — взвешенный случайный (ключи Efraimidis–Spirakis). Каждое использование позы в последних 12 коллекциях уменьшает её вес: `1 / (1 + 0.5·n)`. Moderate-позы получают коэффициент 0.75, а если Preference Memory фиксирует устойчивую (`stable`) проблему анатомии (`bad_hands`, `bad_legs`, `awkward_pose`, `body_proportions`, `anatomy`) — 0.4. Ни одна поза не исключается и не попадает в постоянный список запретов. Один Dislike порог не меняет.
3. **Разнообразие.** Остаток заполняется жадно: побеждает лучший ключ. Множитель ×1.5 получает поза, добавляющая ещё не покрытое направление ракурса (спереди / сбоку / сзади), и ×1.25 — поза, добавляющая не покрытый диапазон крупности (крупно / средне / общий план). Мягкие ограничения: не больше четверти выборки на семейство и около трети (`⌈size/3⌉`) на позы с `anchor: object`. Сначала снимается ограничение по семейству, ограничение по предметам — только если иначе выборку не заполнить. Позы, гарантированные кадрам с явными требованиями, ограничениям не подчиняются: требования пользователя важнее. Свободная тема получает стоячие, сидячие, портретные, прогулочные, полулежачие и вид со спины. Тесты проверяют не меньше четырёх семейств, все три направления ракурса и все три диапазона крупности на 40 seed.
4. **Размер.** `frames × collections + 4` в пределах 8–12. Блок ограничен 8 000 символов. Худший случай — 12 самых длинных записей — помещается целиком. Схема `poseId` строится из фактически перечисленных ID.

Блок для Codex задаёт порядок приоритетов: hard constraints → тема и требования пользователя → релевантные рекомендации Prompt Evolution → каталог → собственный выбор Codex. Codex не должен менять концепцию ради позы. Он не добавляет предметы для опоры, не описывает то, что не видно в выбранной крупности, не повторяет почти одинаковые позы в коллекции и не пишет ID в промпт. Отдельно сказано, что ракурсы и позы не привязаны к номеру кадра и последний кадр не обязан быть видом со спины. Первое сравнение показало, что одной этой фразы мало, поэтому в ревью-правке добавлена история ракурсов (ниже).

## Сохранение позы

| Где | Что |
| --- | --- |
| `prompt-plan.json` | `frames[].poseId` — ID или `free`, как вернул Codex. |
| `batch-plan.json` | `poseSelection: { mode, catalogVersion, seed, sample, recent, cautious, frames, views }`. |
| `collection.json` | `generation.pose: { mode: "auto", catalogVersion }`, `frames[].pose: { id, catalogVersion, promptAsPlanned }`. |
| `scene-NN[-vNN].json` | Тот же объект `pose`. |

- **Seed-варианты.** Наследуют позу кадра: `buildJobs` выставляет её каждому варианту.
- **Перегенерация без правки промпта.** Поза источника наследуется как есть.
- **Перегенерация с правкой промпта.** Происхождение сохраняется, но `promptAsPlanned: false`: промпт уже не тот, что был запланирован. Такое изображение исключается из статистики поз, а интерфейс пишет «промпт изменён после планирования». Повторная перегенерация из такого варианта сохраняет `false`.

`poseId` и `pose` означают **запланированную** позу. `promptAsPlanned` — только признак того, что промпт не редактировали после планирования. Это не визуальная проверка позы или анатомии: PNG никто не анализирует, и нет гарантии, что модель изображений нарисовала именно эту позу.
- **Старые коллекции.** Без `pose`, читаются и отображаются как раньше. Повреждённая запись позы игнорируется. Ранее сохранённые изображения, оценки и планы не изменяются.

## Prompt Evolution

- **Рекомендации.** Действующие рекомендации Preference Memory идут в тот же запрос после блока библиотеки и имеют более высокий приоритет. Алгоритм Prompt Evolution v2 не менялся.
- **Выбор поз.** Устойчивые проблемы анатомии смягчённо понижают приоритет moderate-поз (`cautious`).
- **Связь с отзывами.** Через `frames[].pose` каждое изображение связано с обратной связью на него. В `memory.poses` для каждой позы считаются изображения, коллекции, лайки, дизлайки, Best и победы в Arena. Отдельно учитываются проблемы:
  - кисти — `bad_hands`;
  - ноги — `bad_legs`;
  - тело — `awkward_pose`, `body_proportions`, `anatomy`;
  - ракурс — `bad_angle`;
  - композиция — `composition`, `bad_crop`, `poor_subject_placement`, `repetitive_composition`.

  Это только данные для будущего анализа. В текст для Codex они не попадают, ранжирование и штрафы на их основе не строятся. Best и Arena — общая привлекательность, а не доказательство правильной анатомии.
- **Старые оценки.** Оценки без `poseId` по-прежнему учитываются через анализ фактических промптов v2.

## Интерфейс

- **Дополнительные настройки.** Новый блок «Позы» с выбором «Свободный — Codex придумывает позы сам» и «Авто — из библиотеки». В заголовке секции появился чип «Позы: …».
- **Сводка генерации.** Строка «Позы».
- **Страница коллекции.** У кадра показывается понятное имя запланированной позы, например «Поза по плану: Контрапост, рука на бедре». В подсказке — английское описание и пояснение, что изображение автоматически не проверяется. Для `free` выводится «Поза по плану: своя (Codex)», после правки промпта — «промпт изменён после планирования». Технический ID не показывается.

Проверено в тестовом UI-сервере на фейковых данных: настройка, сводка, запуск в режиме «Авто» и подписи четырёх кадров. Ошибок в консоли нет.

Вывод. Каталог работает как задумано в главном: один запрос, корректные ID, позы встраиваются в сцену, руки описаны конкретнее, опоры естественны. Разнообразие зависит от выборки: дневная получилась сильнее свободного режима, вечерняя — более «мебельной». Проблема финального кадра со спины **не решена** одной инструкцией: 2 из 2 коллекций в режиме Auto закончились видом со спины, у свободного режима — 0 из 2. Выборка мала (4 коллекции), но сигнал совпадает с NS-025. Выводов о реальной анатомии из текста не делается.

Первые два шага выполнены в ревью-правке ниже. Третий — перепроверка на 4–6 коллекциях — остаётся открытым.

## Ревью-правка: разнообразие поз и совместимость с кадром

### Зависимость от окружения

У каждой записи каталога есть поле `anchor`. Оно размечено вручную, а не выводится поиском слов в описании:

| `anchor` | Значение | Позы |
| --- | --- | --- |
| `none` | Без реквизита | 14: ND-P08, P10, P13, P15, P22, P25–P32, P37 |
| `seat` | Обычное сиденье или поверхность: стул, скамья, земля, диван, кровать | 10: ND-P02, P07, P14, P18, P20, P23, P33–P36 |
| `object` | Конкретный предмет или архитектурный элемент: стена, перила, стол, подоконник, ступень, косяк | 13: ND-P01, P03–P06, P09, P11, P12, P16, P17, P19, P21, P24 |

В автоматической выборке поз с `object` не больше `⌈size/3⌉` (3 из 8, 4 из 12). Ограничение мягкое: позы, нужные кадру с явными требованиями, его не учитывают. Оно снимается, только если без этого выборку не заполнить. Тест проверяет его на 60 seed для трёх размеров выборки, а также то, что требование «опираясь на поверхность», которому соответствуют только `object`-позы, по-прежнему получает три совместимые позы. Виды со спины, сидячие и полулежачие позы глобально не исключаются; это тоже проверено тестом. О выборке по ракурсам и крупностям — в разделе «Выборка для Codex», пункт 3.

### Совместимость позы с конкретным кадром

`framePoseIds()` для каждого кадра определяет предложенные ID, совместимые с его явными требованиями (поза, поворот, крупность). `null` означает, что требований нет и подходит любой ID. Codex получает это в виде коротких строк только с ID, без повторения описаний:

```
Frames with composition requirements accept only these ids (any listed id fits the other frames):
- Frame 1: ND-P26, ND-P31, ND-P05 or "free".
- Frame 3: "free" only (no listed pose fits its requirements; keep the requested composition).
```

`validatePlan` проверяет `poseId` относительно требований именно этого кадра (`framePoseIds`). ID, допустимый для другого кадра, отклоняется с сообщением «does not fit this frame's composition requirements». Значение `free` допустимо всегда. Если ни одна поза не подходит, Codex прямо сказано сохранить заданную композицию. Ошибочный план останавливает запуск до ComfyUI, повторного вызова Codex нет. Это проверено сквозным тестом: фейковый Codex намеренно выбирает несовместимый ID, ComfyUI получает 0 отправок. Допустимые ID каждого кадра сохраняются в `batch-plan.json.poseSelection.frames`. Схема JSON остаётся общей: enum всех предложенных ID и `free`. Покадровое правило проверяет валидация. Свободный режим не затронут.

### История ракурсов

`server/poseHistory.ts` читает последние сохранённые Prompt Plans (до 6 многокадровых коллекций) и для каждого кадра определяет направление ракурса через `extractPromptFeatures()` из Prompt Evolution: спереди, сбоку или сзади. Учитываются все кадры — с каталожным `poseId`, с `free` и из свободного режима. Если направление не указано или указано больше одного, кадр помечается «?» и ракурс не угадывается. Например, `extractPromptFeatures` не распознаёт формулировку «right side profile»; Prompt Evolution ради этого не менялся.

Только в режиме «Авто» Codex получает:
- последовательности ракурсов недавних коллекций с пометкой «данные, не правило»;
- если не меньше двух и не меньше половины распознаваемых финальных кадров были видом со спины, мягкую подсказку: не заканчивать коллекцию видом со спины по привычке, выбирать финальный ракурс из концепции. Предлагаются до трёх подходящих не-задних поз из выборки, в порядке сохранённого seed. Отдельно сказано, что задний финал уместен, если этого требует идея.

Если пользователь задал поворот для последнего кадра, подсказка о финале не формируется. Фиксированного порядка кадров нет, задний ракурс в финале не запрещён. История, `rearHeavy` и предложенные позы сохраняются в `batch-plan.json.poseSelection.views`.

На реальных данных пользователя подсказка срабатывает. Последовательности 6 последних коллекций: `front > ? > rear`, `front > side > rear` (три раза), `front > side > ?`, `front > ? > rear`. Все 5 распознаваемых финалов — вид со спины, включая коллекции, созданные в свободном режиме. Значит, это привычка Creative Director в целом, а не только режима каталога.

### Метаданные позы

`poseId` — это запланированная поза. Поле `verified` переименовано в `promptAsPlanned`: оно означает только, что промпт не редактировали после планирования. Это не визуальная проверка. Коллекций со старым полем нет: PR не слит, а сравнения не создают коллекций. Интерфейс пишет «Поза по плану», а в подсказке поясняет, что изображение автоматически не проверяется.

### Повторное текстовое сравнение (2 вызова Codex)

Обе темы в обновлённом режиме «Авто»:
- параметры прежние: `gpt-6.1-sol` · high, Auto Mix 4 кадра, seed выборки 26001 и 26002;
- снимок недавних названий, визуальной истории и Preference Memory тот же — `output/ns-026/compare-KSj6QZ/snapshot.json`;
- история ракурсов прочитана из тех же сохранённых планов;
- Baseline не повторялся.

Оценка по критериям:
- **Статичность.** Не выросла. Вечер стал чуть подвижнее: три стоячих кадра вместо двух сидячих, стола больше нет. День по-прежнему спокойный (лёжа, портрет, профиль, сидя). Прогулочных поз в выборке не было, и Codex их не добавил. Два портрета по грудь из четырёх — крупность разнообразна меньше, чем в первом прогоне.
- **Однотипные опоры.** В выборке их стало меньше: вечер — 4 → 3 из 8. В итоговом плане вечера — **нет**: Codex дважды выбрал `free` и сам добавил опору на парапет и дверную ручку. Хват ручки — активный жест, которого каталог избегает. Дневная коллекция обходится без предметных опор в обоих прогонах.
- **Финальные ракурсы.** Обе коллекции закончились не видом со спины, а вид со спины переместился в середину: кадр 3 вечером, кадр 2 днём. В первом прогоне задний финал был в 2 из 2. Оба финала взяты из предложенных подсказкой поз.
- **Логичность поз.** Сохранилась: опоры существуют в сцене, руки описаны конкретно.
- **poseId ↔ описание.** 6 из 6 каталожных выборов совпадают с текстом промпта, ID в промптах нет. `free`-кадры описаны осмысленно. Вечерняя поза «предплечье на парапете» почти совпадает с ND-P01, но Codex честно отметил её как `free`.
- **Привлекательность концепций.** Сохранилась: «City in Garnet» (гранатовый атлас, опаловые шары), «Summer in Clover» (лиловый хлопок, клевер). Дневная идея почти повторяет первый прогон: тот же снимок и тема.

Вывод. Покадровый контракт и история ракурсов работают как задумано, а в двух повторных коллекциях задний финал исчез. Это 2 коллекции на одном снимке истории, поэтому проблема **не объявляется решённой**: нужна проверка на большем числе тем. Ограничение доли предметных поз в выборке работает, но не ограничивает `free`-кадры, где Codex сам выбирает опору. Если это повторится, следующий шаг — мягкая строка в блоке библиотеки о разнообразии типов опоры и для `free`-кадров. Алгоритм под две темы не подгонялся.

## Ограничения

- Совместимость с темой не проверяется по тексту темы. Выборка разнообразна, а Codex сам отбрасывает неподходящее или ставит `free`.
- Высота точки съёмки (`viewpoint`) не учитывается при совместимости.
- `memory.poses` пока только накапливает данные. Адаптивное ранжирование по оценкам — отдельная задача, когда данных станет достаточно.
- Соответствие описания в промпте выбранному `poseId` не проверяется автоматически, только при ревью. `poseId` — запланированная поза, а не результат проверки PNG.
- Ограничение доли предметных поз действует на выборку, но не на позы, которые Codex придумывает сам (`free`).
- История ракурсов определяется только по однозначным формулировкам `extractPromptFeatures`. Например, «right side profile» не распознаётся и считается «?».
- Реальная анатомия изображений по текстовому сравнению не оценивается. Визуальная проверка — отдельный этап.

## Подготовка к Depth

У каждой позы стабильный ID, ракурсы и крупности в терминах композиции. Каждое изображение помнит свою позу и версию каталога. Будущая интеграция Depth сможет сопоставить `poseId` с картой глубины для подходящего ракурса и включаться только для поз, где NS-025 показал пользу: стоячих, без сложных перекрытий (ND-P25, ND-P26 и похожих). NS-026 Depth не подключает.
