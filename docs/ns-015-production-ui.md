# NS-015 — Рабочий интерфейс

Утверждённый UX NS-013 стал основным интерфейсом NeuroStudio (`web/src/`). Открывается по `http://127.0.0.1:8787`, работает с настоящими коллекциями, генерацией, настройками Codex, ComfyUI, Feedback и экспортом. Интерфейс только русский, рассчитан на Windows Desktop (27″, 2560 × 1440; также 1920 × 1080). Backend NS-014, Creative Director, Prompt Plan v3, workflow ComfyUI, seed, Feedback и правила ZIP не менялись.

## 1. Архитектура frontend

Vue 3 (`script setup`, TypeScript), без Pinia, Vue Router и UI-фреймворков. Состояние — один небольшой модуль `store.ts` на `reactive`/`computed`.

| Файл | Назначение |
|---|---|
| `web/src/api.ts` | Типы ответов API и вызовы (`fetch`); `ApiError` с машинным `code` и исходным текстом |
| `web/src/store.ts` | Навигация, форма «Создание», состояние запуска с сервера, опрос статуса, библиотека, история, каталог Codex, Best и Feedback |
| `web/src/request.ts` | Чистая функция `buildStartRequest(form)`: форма → тело `POST /api/autopilot/start` (без Vue и сети, тестируется отдельно) |
| `web/src/lib.ts` | Помощники над коллекцией: кадры, итоговый кадр, статусы, формулировка причины недоступности ZIP |
| `web/src/errors.ts`, `errorCodes.ts` | Словарь русских сообщений по кодам NS-014; список кодов (зеркало `src/errors.ts`, проверяется тестом) |
| `web/src/ru.ts`, `models.ts` | Русские подписи, склонения, каталог моделей и Auto Mix; **общие** с прототипом (прототип реэкспортирует эти файлы) |
| `web/src/components/` | `CreateView`, `AdvancedSettings`, `SummaryCard`, `LibraryView`, `CollectionDetail`, `Viewer` (Lightbox), `ActivityView`, `ErrorNote`, `Thumb` |

Визуальный язык (тёмная тема, токены, сетки, карточки, цвета моделей) перенесён из `web/prototype/` без изменений. Прототип остаётся независимой UX-референсной версией (`npm run dev:prototype`, `npm run build:prototype`); mock-генератор, фиктивные коллекции, имитация ComfyUI и демо-таймеры в рабочее приложение **не** попали (проверяется тестом). Старые компоненты `CollectionCard`, `CodexSettings`, `CompositionControls`, `Lightbox` удалены: их работающие механизмы (Best, Feedback, Lightbox, `localStorage` Codex) перенесены в новые экраны.

Экран хранится в URL: `#create`, `#library`, `#library/<id>`, `#activity` — перезагрузка и кнопка «Назад» возвращают на тот же экран. Данные всегда берутся из API, не из адреса.

## 2. Соответствие экранов API

| Экран / действие | API |
|---|---|
| Статус ComfyUI, состояние запуска (шапка, «Создание», «Запуски») | `GET /api/status` |
| Каталог моделей Codex и глубины рассуждений | `GET /api/codex/models` (при недоступности — «По умолчанию» и предупреждение) |
| «Сгенерировать» | `POST /api/autopilot/start` |
| Библиотека | `GET /api/collections?limit=50` |
| Коллекция из истории, не попавшая в список | `GET /api/collections/:id` |
| Превью | `GET /api/collections/:id/thumbs/:file` (WebP) |
| Lightbox, скачивание PNG | `GET /api/collections/:id/images/:file[?download=1]` (исходный PNG) |
| Выбор лучшего | `PUT /api/collections/:id/selection` |
| Оценка и заметка | `PUT /api/collections/:id/feedback` |
| ZIP | `GET /api/collections/:id/export` (обычная ссылка на скачивание; ZIP на клиенте не собирается) |
| История запусков | `GET /api/runs?limit=50` |

## 3. «Создание»

Параметры: тема (до 200 символов), коллекции 1–3, кадров 1–4, вариантов 1 / 2 / 4, режим моделей (Автоподбор / Только … / Для каждого кадра), модель по кадрам при Custom; в «Дополнительных настройках» — модель Codex, глубина рассуждений, общая композиция и композиция отдельных кадров.

Преобразование формы в запрос (`buildStartRequest`):

- Автоподбор → `{mode:"auto"}`; Только X → `{mode:"only", model:"X"}`; Для каждого кадра → `{mode:"custom", perScene:[…]}` ровно из `frames` моделей.
- `composition` отправляется только если что-то задано **для активных кадров** (или в общих настройках); `composition.scenes` обрезается до `frames`. Настройки скрытых кадров остаются в форме и возвращаются при увеличении числа кадров. «Авто» и «Как в общих» передаются как есть (`"auto"`, `"inherit"`).
- `codexModel`/`codexReasoningEffort` добавляются только при явном выборе («По умолчанию» — поля не передаются). Выбор хранится в `localStorage` (`neurostudio.codex`) как раньше; недоступное в каталоге значение сбрасывается на «По умолчанию».
- Запрос — глубокая замороженная копия формы на момент нажатия; последующие правки формы его не меняют.

Перед запуском крупно показано число изображений и формула (`2 коллекции × 3 кадра × 2 варианта = 12 изображений`).

## 4. Запуск, статус и история

**Источник истины — сервер.** Локальных таймеров и имитации прогресса нет.

- Нажатие «Сгенерировать» отправляет **один** запрос. Повторный клик (в том числе одновременный) и клик при уже идущем запуске не отправляют ничего; автоматического повтора нет. Ответ 202 сразу кладётся в состояние запуска.
- Во время запуска форма редактируема (для следующего запуска), текущий запуск от неё не зависит (замороженный запрос + снимок настроек на сервере).
- Опрос `GET /api/status`: раз в 2 с во время запуска и при потере связи, раз в 5 с в покое; **один запрос одновременно**, устаревшие ответы отбрасываются (после 202 запрос, начатый раньше, игнорируется).
- Потеря связи (сбой опроса) не завершает запуск: на экране остаётся последнее известное состояние, показывается предупреждение «Нет связи с сервером…», опрос продолжается.
- Перезагрузка вкладки: состояние запроса восстанавливается из `/api/status` (идёт ли запуск, `done / total`, текущая коллекция и кадр). Если сервер перезапускался, запуск не изображается идущим: статус `idle`, а коллекция со статусом `running` на диске показывается как «Прервано».
- Номер текущего варианта (seed) не показывается — backend его не отдаёт; показывается номер кадра, когда он известен.
- Библиотека работает во время запуска; список обновляется каждый опрос, пока запуск идёт, и при завершении.
- Ошибка запуска сохраняется как раньше: остановка без повторов, `prompt_id` и созданные PNG остаются.

**«Запуски»:** текущий запуск (из `/api/status`: этапы, прогресс, коллекции запуска, ошибка) и история (`/api/runs`: дата, тема, коллекции × кадры × варианты, режим моделей, статус, ошибка, ссылки на коллекции). Видны завершённые, неудачные, прерванные запуски, ошибки Codex на этапе планирования («Коллекции не создавались»), частично сохранённые. Запись запуска создаётся до обращения к Codex (NS-014A), поэтому планирование видно в истории сразу. Параметры Codex текущего запуска берутся из его записи в истории. Автоматического Resume/Retry нет.

## 5. Библиотека и просмотр

Карточка: русское название (иначе исходное английское), статус, число кадров и вариантов, превью каждого кадра (итоговый → первый готовый → состояние), метка выбора Best, оценка, готовность к экспорту. Поиск по обоим названиям; фильтры «Все / Требуется выбор / Готово к экспорту / С проблемами» работают по реальным данным и серверному `export.ready`. Список ограничен лимитом API (50 свежих коллекций); при достижении лимита интерфейс прямо пишет «показаны последние 50, более ранние не отображаются». Старые коллекции (без `frameCount`, `generation`, русских полей) показываются полностью: 4 кадра, английские названия, «Нет данных» в параметрах.

Просмотр: все кадры 1–4 крупно, все seed-варианты (миниатюры), выбор и снятие лучшего, русское краткое описание кадра (иначе английское), модель, параметры генерации (тема, режим моделей, Codex, время, композиция по кадрам, seed и `prompt_id`), Feedback, ZIP. Lightbox: оригинальный PNG, ← →, `B` (лучший), `Esc`, скачивание PNG. Изображения на клиенте не перекодируются: превью — WebP с сервера, увеличение и скачивание — исходные PNG.

**Best:** выбор показывается сохранённым только после ответа сервера (состояние берётся из ответа); при ошибке состояние не меняется, показывается причина.

**Feedback (NS-010, формат `feedback.json` прежний):** оценка 1–5 (повторный клик снимает), теги (русские подписи, технические id прежние), заметка до 500 символов, сохранение сразу. Сохранения идут **по одному на коллекцию**: быстрые изменения объединяются, отправляется последнее состояние черновика, поэтому медленный старый ответ не затирает новую оценку.

**Экспорт:** один кадр с одним вариантом — сразу; несколько вариантов — нужен Best для каждого кадра; причина недоступности по-русски («Выберите лучшие: 2/4», «Нет готового изображения: 1 кадр»). Готовность решает сервер.

## 6. Ошибки

Тело ошибки API: `{error, code}`. Интерфейс показывает по `code` русское сообщение, а исходный технический текст (в том числе слова ComfyUI и Codex) — в раскрываемом «Подробности»:

| Код | Сообщение (кратко) |
|---|---|
| `INVALID_GENERATION_SETTINGS` | Настройки генерации не приняты |
| `ALREADY_RUNNING` | Генерация уже идёт |
| `COMFY_UNREACHABLE` | ComfyUI недоступен |
| `PLAN_INVALID` | Codex вернул план, не прошедший проверку; изображений нет |
| `CODEX_FAILED` | Codex не смог составить план; изображений нет |
| `GENERATION_FAILED` | Ошибка при создании изображений; сохранённое осталось |
| `EXPORT_INCOMPLETE` | ZIP пока недоступен |
| `COLLECTION_NOT_FOUND` | Коллекция не найдена |
| `INVALID_REQUEST` | Сервер не принял запрос |

Неизвестный или отсутствующий код → «Что-то пошло не так», недоступный сервер (сеть) → «Сервер NeuroStudio не отвечает»; технический текст остаётся в «Подробности». Необработанный JSON и stack trace основным сообщением не показываются.

## 7. Совместимость со старыми коллекциями

Ничего не мигрируется и не переписывается. Нет `frameCount` → 4 кадра (ответ сервера); нет русских полей → исходные названия и описания; нет `generation`/`codex` → «Нет данных (коллекция создана до учёта настроек)»; старые `batch-plan.json` читаются в «Запусках». Проверено тестами и на тестовых данных (раздел 9).

## 8. Локальный запуск

```bash
npm install
npm start          # vite build web && tsx server/index.ts  →  http://127.0.0.1:8787
```

ComfyUI (по умолчанию `http://127.0.0.1:8188`) и Codex CLI нужны только для настоящей генерации. Разработка интерфейса: `npm run dev:server` + `npm run dev:web` (Vite, `http://127.0.0.1:5173`, прокси `/api`). Прототип: `npm run dev:prototype`.

**Просмотр без Codex и ComfyUI** (изолированный тестовый сервер на фиктивных данных, порт 8791):

```bash
npm run build
npx tsx scripts/ui-test-server.ts --slow
```

Скриншоты из этого документа: `npx tsx scripts/ui-screenshots.ts` (headless Chrome, тестовые данные, фиктивные ComfyUI и Codex).

## 10. Известные ограничения

- Список коллекций и история ограничены лимитом API (50); пагинации нет.
- Параметры композиции текущего запуска в «Запусках» не показываются: `/api/status` и `/api/runs` их не отдают (в карточке готовой коллекции — показываются).
- Состояние Feedback/Best между двумя вкладками не синхронизируется до обновления списка.
- Серверная проверка id коллекции (`^[A-Za-z0-9._-]+$`) допускает `.` и `..`; в адресе интерфейса такие id не принимаются, сервер не менялся.
- Качество реальных изображений и работа с настоящим ComfyUI в этом PR не проверялись (только тестовые данные и фиктивные клиенты).
